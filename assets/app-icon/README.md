# Ramus app icon

Two designs, each in a light (paper) and a dark (graphite) appearance:

- `monogram/`: an R whose leg leaves the bowl as a branch. This is the icon
  the app ships (`icon` and `macos.icon` in `mygo.json`).
- `fork/`: the branch glyph, a trunk between two commits and one branch tip.
  Kept as a backup design; nothing uses it.

Everything here is generated by `generate.go` from one table of shapes and
colors. Change the table, never an output, then regenerate:

```bash
go run assets/app-icon/generate.go
```

It needs a Mac with Icon Composer, which ships inside Xcode 26 and later:
the rasters are rendered by its `ictool` from the `.icon` document, so they
carry the same Liquid Glass treatment macOS draws.

## Contents

Each design directory holds:

| Path | What it is |
|------|------------|
| `AppIcon.icon/` | Icon Composer document with light and dark appearances; the macOS icon |
| `svg/icon-{light,dark}.svg` | Flat masters on the macOS icon grid, without glass |
| `png/icon-{light,dark}-{1024,2048}.png` | Hi-res renders |
| `linux/{light,dark}/NxN.png` | 16 to 1024 px set |
| `windows/ramus-{light,dark}.ico` | 16 to 256 px |

## Notes

- Icon Composer fills every path and ignores strokes, so the layers are
  filled outlines; `generate.go` outlines the strokes.
- The glass is kept low: a specular edge and a soft shadow, no translucency,
  so the glyph stays solid at 16 px.
- `ictool` writes 16-bit Display P3; the generator converts each render to
  8-bit sRGB, which Windows icons need.
- Windows and Linux have no per-appearance app icon. mygo renders theirs from
  the light 1024 px PNG; the dark sets are there for manual use.
