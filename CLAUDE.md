# Ramus

Git client built to be lightweight and fast on large repositories: Go, with
native UI drawn on the GPU by [mygo](https://github.com/egoist/mygo). No
webview, no cgo.

Working notes are untracked, in `docs/internal/`; `research/` there holds the
survey of existing clients this design answers. Never commit them.

## Commands

```bash
go tool mygo dev      # run with live reload
go tool mygo build    # package the app into build/
scripts/check.sh      # the full gate: gofmt, vet, engine import boundary, no network of ours, tests
go run ./scripts/coldstart <binary>  # time to first frame; CI runs it, it opens AppKit
gh workflow run ci.yml   # CI and soak.yml run only when started by hand
git push origin vX.Y.Z   # release.yml: builds and publishes a release of mygo.json's version
gh workflow run release.yml               # a dry run of main: builds and notarizes, uploads nothing
gh workflow run release-notes.yml -f ref=main  # preview the notes Claude writes
go run ./scripts/verifyrelease vX.Y.Z    # check a release whole: files, checksums, manifests, signatures
RAMUS_FIXTURES=~/Projects/ramus-fixtures go run ./bench -runs 5 -out bench.json  # the benchmarks
```

## Layout

- `main.go`: starts the app and opens its windows, or, when git or ssh
  starts it as SSH_ASKPASS, runs as the askpass helper
  (`internal/askpass`) and exits; nothing else lives here. `windows.go` keeps the windows, one `ui.App` each, sharing
  the stores, the settings and git. `probe.go` is the cold-start probe
  mode (`RAMUS_PROBE_STARTUP`), which `scripts/coldstart` times;
  `.github/workflows/ci.yml` runs both. `about.go` is the About window and
  the update check, the app's one use of the network of its own, made
  when the user asks: mygo's updater reads the releases of
  PythonShe/ramus, signed with the key whose public half is in
  `mygo.json`; the secret half is the repository's
  `MYGO_UPDATER_PRIVATE_KEY` secret and never goes in it.
- `.github/workflows/release.yml`: on a `vX.Y.Z` tag, runs CI and
  builds the macOS app, signed with the Developer ID of
  `APPLE_CERTIFICATE` and notarized with the App Store Connect key of
  `APPLE_API_KEY`, and the Linux and Windows packages, unsigned, into a
  draft release. Those secrets are the repository's; the build job runs
  in the `release` environment. Once every build succeeded, `release-notes.yml` writes
  the notes (a `## X.Y.Z` section of `CHANGELOG.md` written by hand
  wins), which go into the release and its update manifests, and the
  release, checked whole by `scripts/verifyrelease`, is published: as a
  prerelease, never the latest, when its version has a pre-release
  suffix. It names
  the notary profile in the runner's `mygo.json` only, so local builds
  stay ad hoc.
- `internal/ui/`: app state and views. Views are tested without a window
  through `ui.NewTester`.
- `internal/git/`: the engine. It imports nothing from mygo; `check.sh` fails
  if it does.
- `bench/`: the benchmarks, a program apart from the product: each case
  runs in a process of its own and records the machine, p50, p95 and peak
  memory. Cases on fixtures only read them; the others make repositories
  in a temporary folder. `soak` runs in a CI workflow of its own.
  `bench/monorepo` generates the 390k-file fixture; `docs/benchmarks.md`
  holds the method and the published numbers.
- `locales/`: the catalog of every text a user reads, `en.json`, in ICU
  MessageFormat; English is the only language so far. `mygo dev`, `mygo
  build` and `go tool mygo generate` write `catalog_gen.go` from it, one
  typed function per message; never edit that file. A message is a whole
  sentence with placeholders and ICU plurals, never pieces joined in Go.
  `TestTextComesFromTheCatalog` fails on literal text in a view. The
  engine cannot import it, so the names of its operations and git's own
  messages stay as they are.
- `internal/licenses/`: the licenses of Ramus and of all it links, for the
  About window, in `licenses.json.gz`, which its `generate.go` writes; run
  it when a dependency changes, which `TestCoversTheBuild` reports.
- `internal/ui/fileicon/`: file icons from the Symbols icon theme (MIT):
  `icons.tar.gz` and `tables_gen.go` are generated by its `generate.go`
  from a Symbols checkout; never edit them, see its README.
- `assets/app-icon/`: the app icon in every format, generated by
  `generate.go`; see its README before touching an output.
- `assets/cards/`: the product cards for the places that list Ramus, the
  mygo showcase among them: pages of HTML over screenshots that
  `TestScreenshot` in `internal/ui` draws, rendered by `render.sh`. Their
  figures are those of `docs/benchmarks.md`; see its README.
- `.agents/skills/`: mygo's own agent skills, written by
  `go tool mygo install-skills .`; rerun it after a mygo bump instead of
  editing them. Read `mygo-maintenance` before changing a view.

## Rules

- Reads go through our own readers of git's on-disk formats; everything that
  writes runs the `git` executable, so hooks, signing and credentials behave
  as in the terminal.
- When the engine meets something it does not support (SHA-256 objects,
  partial clones, sparse or split indexes), it hands that repository or
  operation to `git` instead of guessing. Refs are read natively in both
  the files and the reftable format.
- `git` is the oracle: a reader is tested by comparing its output with
  git's on real repositories.
- The main thread never waits on I/O, a subprocess or a lock held by
  background work. Work runs in goroutines and publishes through
  `Window.Update`; stale work is cancelled.
- Subprocesses are bounded in number, cancellable and time-limited.
- Any collection that can grow goes in `List`, `Table` or `Tree`, never a
  `Scroll` that builds every row: a mygo frame costs what the view builds.
- Large data stays out of the garbage collector's way: memory-mapped files,
  and flat pointer-free slices with one shared byte buffer for text, not one
  object per commit.
- Every cache has a byte budget. Everything a repository owns (maps,
  goroutines, subprocesses, watchers) shares one lifetime that ends when the
  repository closes. The app must not need restarting.
- Zlib inflate uses `github.com/klauspost/compress`, behind an interface in
  the engine so another implementation can replace it.
- mygo is pre-1.0 and pinned in `go.mod`. A bug in it is fixed by a pull
  request upstream, not by a fork or a workaround here.

## Commit scopes

`git` (engine), `ui`, `docs`, `workspace` (root files, scripts, mygo config);
combine as `git,ui`.
